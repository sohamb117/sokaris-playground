## Root cause (confirmed 2026-08-16T18:47:19-07:00)
- Mechanism: `src/ui/image-decoder.ts` returned every source pixel, so an 800×768 RGBA image became 2,457,600 decimal VM literals and a 7,380,348-character generated binding. The VM traps while parsing that numeric-literal AST; the transform loop is not involved because `result = 1` still traps with the binding, while a same-length padded scalar source succeeds.
- Evidence: 32² produces 19,834 source characters and completes invert in about 1.65s; 64² completes in about 17.5s; 128² takes about 257s; 800×768 traps in about 6s. The failing-first decoder test observed `width=800`, `height=768`, and 2,457,600 channels.
- Toggle proof: a 32×32 image completes the same `load(...) ▷ invert` pipeline; the full 800×768 decode traps. Bounding the browser raster input removes the pathological numeric-literal count without changing VM-side transforms.
- Fix scope: `src/ui/image-decoder.ts`, focused unit/e2e tests, and concise image-boundary documentation.
